# 2026-07-22 字幕批处理失败：语义回流与最终门禁

## 现象

`Live Charting Program 1_chunked - 副本` 在 09:58:30 至 10:12:44 的批处理没有导出。最终门禁报告 10 个 `incomplete_bilingual` 关键问题：#274、#824、#941、#1309、#1310、#1311、#1333、#1877、#1885、#1905。

这里的标签较笼统：这些条目实际都有双行，但中文目标行退化成仅含数字、英文名或标点，例如 `355`、`Darko，`、`。`，所以被规则识别为 `missing_chinese_target`。

## 已排除的原因

- 不是网络、限流或模型 API 错误：此时间窗口内的请求均记录为 HTTP 200；日志中的忠实度审校、润色和全文一致性审计都报告失败批次 0、最终失败 0。
- 不是初次翻译失败：`AFTER_TRANSLATE.srt` 中这些位置仍是完整中文句子。例如含 `Darko` 的原文已译为“Darko，我不看开盘价和收盘价。我只看现货交易时段。”，含 `355` 的原文已译为“看看会不会回到那位说的价位。看看会不会回到355。”。
- 因而提高或降低请求并发不能解决这个失败。

## 根因

所有模型阶段之后，`UnifiedPipeline.run()` 调用 `reflow_semantic_entries()`（`core/pipeline.py:705`）。该函数在 `core/semantic_units.py:177` 把一个完整目标句按源 cue 分组；它调用 `split_target_by_weights()`（`core/semantic_units.py:100`）按字符长度/权重切分，而非按中英文语义边界对齐。

在源 cue 边界恰好落到人名、数字或句号附近时，完整译文就被切成无中文语义的碎片，然后与对应英文源 cue 组成“看似双行”的字幕。最终 `srt_lint` 正确地拒绝它们，质量门禁也正确停止了导出。真正错误在回流映射，不能靠放宽门禁、把 `355` 视作合格译文来掩盖。

## 相关但不同级别的日志项

- “拒绝不安全合并组”：分段阶段的保护性告警，表示不愿冒险合并 cue；不是失败。
- “高阅读压力 10”“大重叠 25”：非关键质量提醒，不会阻止导出。
- “Source integrity 差异（已降级为警告）”：与这次错误同源的强信号；目前 `core/pipeline.py:740-752` 将其降级，导致损坏的回流结果直到最后门禁才被挡住。这是流程设计缺口。

## 缺失的回归覆盖

现有语义完整性测试只验证源 cue 与拼接后的目标字符没有丢失，未验证每个重新分配的双语 cue 都拥有可用、语义对应的中文目标。因此无法捕捉“总体字符未丢、单条字幕已失真”的情况。

## 修复方向

1. 回流只能在有可证明的语义边界时拆分；不能可靠对齐时保留原有双语条目，而不是按字符切片。
2. 回流后立即逐 cue 校验目标行（含中文、非空、与源分组对应）；失败则回退该组的回流结果。
3. 让这类 source-integrity 差异保持阻断或自动回退，不能仅降级成警告。
4. 为本次 10 个案例（人名、数字、纯标点、重复词）建立端到端回归测试。

状态：根因已确认；第一阶段已在本次修复中实施，第二阶段作为后续的细粒度时间轴增强保留。

## 修复设计（2026-07-22）

### 不变条件

1. 质量门禁继续拒绝“实质英文原文 + 无中文目标”的条目；不能把数字、英文名或标点碎片豁免为正常翻译。
2. 不能要求人工审核才能导出。只要完整译文已经存在，系统必须自动保留它。
3. 每一个源 cue 必须恰好覆盖一次、顺序不变；一条输出字幕可以合法覆盖一组连续 cue。

### 第一阶段：立即消除数据损坏（安全回退）

在 `reflow_semantic_entries()` 中删除生产路径的字符权重目标拆分。只有能从显式语义边界证明对应关系的情况才允许拆分；当前没有这种证明，因此多 cue 的语义单元默认输出为一条、时间覆盖该组首尾 cue，目标保留为完整译文，源文本保留为该组原文。

这不是原文兜底：它保留的是已经通过翻译和审校的完整中文。若目标本身为空，才维持现有的明确失败/源文本兜底策略。

回流后增加 `validate_reflow_assignment()`：验证每个输出条目含有完整目标、实质英文源对应中文目标、源 cue 连续且恰好覆盖一次。校验失败时自动回退为该语义单元的未拆分版本，并记 `reflow_alignment_fallback`；只有未翻译的内容才让最终门禁失败。

### 第二阶段：恢复细粒度时间轴（显式映射）

扩展翻译/合并阶段的结构化输出，让模型返回连续分组：`[{source_indexes: [...], target_text: "..."}]`。模型可以把多个原 cue 合为一个完整句，但每个源 cue 必须在且仅在一个连续分组中。服务端验证 ID 覆盖、顺序、目标语言和目标拼接完整性；无效输出不用字符算法猜测，直接走第一阶段的完整语义单元回退。

这样“如何拆中文”由了解语义的翻译步骤明确给出，回流步骤只应用已验证的映射，不再翻译后猜边界。

### 完整性与可观测性

- 将回流映射完整性与单纯的源 cue 签名检查分开。前者失败必须回退/阻断；后者只在 finalizer 有可证明的、保留覆盖的合并时允许变化。
- 日志新增每个回退的语义单元 ID、原因、是否保留了完整译文；UI 汇总为“自动保留完整译文 N 组”，而非“待人工审核”。
- `Source integrity` 不能再把内容损坏降级成普通警告。

### 回归与验收

在 `tests/test_source_semantic_integrity.py` 添加本次 #941（Darko）、#1309--#1311（355/句号）、#1333（Leonardo）、#1877（重复词）、#1885（UD2）、#1905（数字）案例。每例验证：目标不被拆为碎片、源 cue 覆盖一次、最终 lint 无 `missing_chinese_target`、质量门禁可通过。再跑全量测试与同一 SRT 的端到端复现。
