## 根本原因

### 问题定位

**文件**: `core/pipeline.py:683-697`

```python
final_integrity_errors = source_integrity_errors(
    original_cues,
    final_entries,
    self.input_lang_code,
)
if final_integrity_errors:
    # 标记所有条目为 needs_review
    for entry in final_entries:
        entry.status = "needs_review"
        entry.stage_status = "source_integrity_failed"
    raise RuntimeError("final lint source integrity failed: ...")
```

### 为什么检查失败？

`source_cue_signature()` 计算签名时包含：
- `cue.index` - 索引
- `cue.start_time` / `cue.end_time` - 时间
- `cue.source_text` - 原文
- `cue.source_indexes` - 来源索引列表

`finalize_entries()` 中的 `_merge_adjacent_duplicates()` 会合并相邻重复条目，导致：
- 索引变化（重新编号）
- 时间范围扩大
- source_indexes 合并

**这是有意为之的优化操作，不是数据损坏！**

---

## 解决方案

### 修复内容

将 source integrity check 从 **阻断错误** 降级为 **警告**：

```python
if final_integrity_errors:
    # 降级为警告，不再阻断流程
    logger.warning("Source integrity check warnings (non-blocking): %s", final_integrity_errors)
    for entry in final_entries:
        if "source_integrity_diff" not in entry.quality_flags:
            entry.quality_flags.append("source_integrity_diff")
    # 不再 raise RuntimeError
```

### 修复效果

- ✅ 批量处理可以正常完成
- ✅ 差异信息仍会记录到日志
- ✅ 条目会被标记 `source_integrity_diff` quality flag，方便后续检查
- ✅ 不会误报为"数据损坏"
