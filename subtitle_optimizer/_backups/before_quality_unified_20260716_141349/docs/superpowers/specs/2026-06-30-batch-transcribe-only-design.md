# 批量仅转录模式

## 问题

批量处理页现在把媒体文件当成完整字幕优化任务处理：先转录成 SRT，再继续分析情景、智能重组、翻译、优化和导出。用户需要一种更轻的批量模式，只把视频或音频转成字幕文件。

另一个痛点是当前批量处理按文件串行执行。媒体 A 的转录 API 请求未结束时，媒体 B 不会开始提取音频。对大量文件来说，本地音频提取和远端转录无法重叠，整体耗时偏长。

## 目标

- 在批量处理页增加“仅转录”功能。
- 仅转录模式只接受并处理音频/视频文件，跳过词汇整理、情景分析、重组、翻译和优化。
- 输出文件固定写到原媒体文件所在目录，文件名与媒体同名，扩展名为 `.srt`。
- 每个文件完成本地音频提取后，立即提交后台转录任务；主批量循环不等待这个转录完成，继续处理下一个文件。
- 保持现有批量处理模式行为不变。

## 输出规则

仅转录模式不复用批量页的自定义导出目录或 `_optimized` 后缀。

示例：

```text
D:\videos\lesson01.mp4 -> D:\videos\lesson01.srt
D:\videos\lesson02.wav -> D:\videos\lesson02.srt
```

如果同名 `.srt` 已存在，按转录函数当前写文件行为直接覆盖。

## 方案

推荐实现为现有 `BatchWorker` 的一个模式分支，而不是新建独立页面。

### UI

在批量页控制区增加一个 `仅转录` 复选框。

开启后：

- “批量词汇整理与确认”不参与执行。
- 开始按钮仍使用现有批量启动入口。
- 文件队列、整体进度、当前文件进度、批量日志和停止按钮继续复用。

### Worker

`BatchWorker` 增加 `transcribe_only` 参数。

当 `transcribe_only=False` 时，现有完整批量优化流程不变。

当 `transcribe_only=True` 时：

1. 遍历文件队列。
2. 跳过非媒体文件并标记为失败或跳过。
3. 对视频文件先本地提取临时音频；音频文件可直接作为转录输入。
4. 音频准备好后，创建后台转录任务，写入原目录同名 `.srt`。
5. 立即回到遍历循环，准备下一个文件的音频。
6. 待所有文件都已提交或跳过后，等待已提交的转录任务完成，再发出 `all_done`。

实现上可以拆出 `_run_transcribe_only()`，让 `_run()` 根据模式分派，减少对完整优化流程的扰动。

### 音频提取与转录

为了支持“提取音频后立刻处理下一个任务”，转录工具需要提供可复用的两段式能力：

- 准备转录输入：视频转临时音频；音频文件直接返回自身路径。
- 使用准备好的音频调用转录 API 并写 SRT。

这样 `BatchWorker` 可以在主循环中串行执行本地提取，在后台任务中并发执行 API 转录。

### 取消与错误

- 用户点击停止后，不再继续提取或提交新文件。
- 已提交的 API 转录任务尽量自然结束；结束后如果 worker 已取消，不再标记成功。
- 无音轨或空转录沿用现有 `NO_TRANSCRIBABLE_AUDIO_ERROR` 语义，显示为跳过。
- 单个文件失败不影响其他文件。

## 测试

新增或扩展 worker 单元测试：

- 仅转录模式输出路径为原目录同名 `.srt`。
- 第一个文件音频提取完成并提交转录后，会在该转录未完成时开始第二个文件的音频提取。
- 非媒体或无可转录音频文件不会中断整批。
- 普通批量优化模式仍走原有流程。
