## P1. 术语表子串匹配注入错误强制译法 🔴

### 现象

用户的术语表是 660 条**期货/订单流交易**术语。跑一个 NASA 物理科普视频，`filter_glossary_by_entries()` 从中"筛出" 11 条认为相关：

```
balance->平衡状态    DOM->盘口        HE->猪肉期货（HE）   lot->手
R->R（风险回报比）    ratio->比率      resistance->阻力位   retest->回测
sim->模拟交易        structure->价格结构   support->支撑位
```

这 11 条**全部**作为**硬性约束**写进了每一个 prompt：

```
★ 【强制术语表】遇到以下英文专业词汇，必须严格统一翻译为对应中文，绝不允许替换为同义词或意译：
  - "HE" 必须译为 "猪肉期货（HE）"
  - "R" 必须译为 "R（风险回报比）"
  - "retest" 必须译为 "回测"
  - "sim" 必须译为 "模拟交易"
  ...
```

### 根本原因

**文件**: `core/workers.py` — `filter_glossary_by_entries()`

```python
all_text = " ".join(line for e in entries for line in e.lines).lower()
...
src = line_s.split(sep, 1)[0].strip().lower()
if src and src in all_text:        # ← 纯子串匹配，无词边界
    kept.append(line_s)
```

实测这 11 条到底是怎么匹配上的：

| 术语 | 子串命中 | **独立单词命中** | 实际匹配到的位置 |
|------|---------:|----------------:|------------------|
| `he` | 115 | **0** | t**he** / **he**y / t**he**re |
| `r` | 275 | **0** | 匹配一切含字母 r 的词 |
| `sim` | 1 | **0** | **sim**ple |
| `support` | 1 | **0** | **support**ing |
| `balance` | 2 | **0** | **balance**d |
| `dom` | 1 | **0** | ran**dom** |
| `ratio` | 3 | **0** | accele**ratio**n |
| `retest` | 1 | **0** | **retest**ing |
| `lot` | 3 | 3 | a **lot** of（词义仍不对） |
| `structure` | 3 | 2 | 工程语境，非"价格结构" |
| `resistance` | 2 | 2 | "**resistance** of an object to motion"，非"阻力位" |

**11 条里 8 条独立单词命中为 0**，纯属子串误伤。剩下 3 条虽然是真单词，但词义完全不对。

### 实际损害

已产出**一处确凿错译**：

```
[58] 原 Testing and retesting. Looking for the best answers.
     译 反复回测，只为找到最佳方案。
                ^^^^  硬件测试语境下"回测"是金融术语，应为"反复测试/反复试验"
```

`HE->猪肉期货` 和 `R->风险回报比` 这次侥幸没被模型采纳——但它们在 prompt 里的措辞是"**必须**严格统一翻译"、"**绝不允许**替换"。换个模型或换个批次就可能爆掉。

### 建议修复

按输入语言的文字系统分别处理——拉丁语系用词边界，CJK 无词边界只能靠长度与出现次数：

```python
def _glossary_source_appears(source: str, haystack: str, lang_code: str) -> bool:
    src = source.strip().lower()
    if not src:
        return False
    if lang_code in ("zh", "ja", "ko"):
        # 无词边界可用；单字符术语误伤率过高，要求至少两个字符
        return len(src) >= 2 and src in haystack
    # 拉丁语系：必须整词命中，避免 the->he / random->dom / retesting->retest
    return re.search(rf"(?<!\w){re.escape(src)}(?!\w)", haystack) is not None
```

另外建议：对**单字符**或**两字符**的拉丁术语（`R`、`HE`、`sim`）额外要求出现次数 ≥2，或干脆要求大小写完全一致（`HE` vs `he`），否则这类缩写的误伤代价太高。

## P2. ASR 听错的专名被提升为强制术语，反被审校保护 🔴

### 现象

阶段一情景分析从转录文本里提取了这三条"术语"：

```
Ascensivore 1 -> Ascensivore 1
PataBort 1    -> PataBort 1
CentaBort 1   -> CentaBort 1
```

这三个都是 **ASR 听错的产物**。真实的 NASA 项目名是：

| ASR 输出 | 实际应为 |
|----------|----------|
| PataBort 1 | **Pad Abort 1**（PA-1，猎户座发射台中止测试） |
| CentaBort 1 | **Ascent Abort 1**（AA-1，上升段中止测试） |
| Ascensivore 1 | **Ascent Abort 1** |

它们被写进强制术语表后，成品里原样保留：

```
[47] 译 比如在 PataBort 1 飞行测试和接下来的 CentaBort 1 测试中，
        我们会用数千磅压舱物来满足质量和重心要求
[54] 译 我身后的是 Ascensivore 1 飞行测试的隔热罩...
```

### 为什么这个特别严重

这不是"审校没抓到"，而是**审校被明令禁止去碰它**。忠实度审校和一致性审校的 prompt 都写着术语表是最高优先级：

```
system += "\n\n【强制术语表】\n" + glossary        # fidelity_review_batch
"强制术语表优先级最高。"                            # _consolidate_system
"术语表是硬性约束，优先级高于文采"                    # _optimize_batch_impl
```

**一个上游的识别错误，被提升成了下游三轮质检都不许修改的权威。** 这是质量流水线里最危险的一类缺陷：错误不仅没被拦住，还获得了保护。

而且注意这三条都是**恒等映射**（source == target），翻译价值为零——它们对译文的唯一作用就是"锁死这个拼写"。

### 建议修复

三层，从便宜到彻底：

1. **丢弃恒等映射**（最便宜，立刻见效）
   `_term_rules_to_glossary_text()` 里跳过 `source.casefold() == target.casefold()` 的条目。这类词条不提供任何译法信息，只提供锁定效果，而锁定一个未经确认的 ASR 输出没有收益。

2. **要求跨样本出现**
   `_sample_entries_for_analysis()` 取整片 80 条样本。可以要求一个候选专名在样本中出现 ≥2 次才进术语表；ASR 的偶发错听通常只出现一次。

3. **给忠实度审校开一个口子**
   现在的 prompt 是"原译文正确时必须原样保留"。可以增加一条：允许对**明显不是有效英文专名**的词标记存疑，但不自行改写——输出到质量标记里交人工确认，而不是静默锁定。

## P3. 忠实度审校漏掉一处真实漏译 🟠

### 现象

```
[15] 00:01:20,100 --> 00:01:29,600   （9.5 秒）
 原  And there's also an inertia component, which is a function of the mass
     and how far away that mass is from the center of gravity
     or the point that you want the inertia to be.
 译  还有惯性，它取决于质量及其与重心的距离
```

**丢掉了 "or the point that you want the inertia to be"** ——这是实质技术信息：惯性是相对**任意选定参考点**计算的，不只是相对重心。物理科普里丢掉这个限定条件是硬伤。

而且这条有 **9.5 秒**画面时间只用了 18 个字（约 1.9 字/秒，远低于舒适上限），**完全有空间补全**。

忠实度审校那一轮修正了 9 条，但漏了这条。

### 两个可改的点

**① 提示词：缺少"信息点逐项核对"的强制步骤**

现在 `fidelity_review_batch` 的 prompt 是：

```python
"逐条检查 src 与 tgt，只修复以下问题：漏译、误译、否定反转、条件丢失、"
"因果/转折关系错误、数字/单位/人名/术语错误、指代错误。\n"
```

只是**列出**了要查什么，没有要求模型**先枚举原文信息点再逐项核对**。

有意思的是，项目里已经有这个写法——但只写在 `_optimize_batch_impl` 的**重试** prompt 里：

```python
"6. 【覆盖自检】返回前逐条检查：tgt是否完整覆盖了src的主语、动作、条件、原因、结果和关键术语"
```

**主翻译 prompt 和忠实度审校 prompt 都没有这一条。** 建议把覆盖自检提到忠实度审校——那一轮的全部职责就是查这个：

```
【核对方法】对每条先在心里列出 src 的信息点清单：主语、动作、对象、条件、
原因、结果、限定语（"or ..."、"unless ..."、"except ..."）、数字与单位。
再逐项确认 tgt 是否都有对应。缺任何一项都必须补上，不得因为"读起来通顺"就放过。
特别注意并列结构中的第二个分支（A or B 中的 B）最容易被整段丢掉。
```

最后一句是针对本例的：丢的正是 `A or B` 里的 B。

**② 流程：审校看不到还有多少画面时间**

审校 prompt 只给 `src` 和 `tgt`，模型不知道这条有 9.5 秒、当前只用了 18 字。它无法判断"该补全"还是"必须精简"。

建议在送审的 item 里带上时长预算：

```python
items = [{
    "id": entry.index,
    "src": ...,
    "tgt": ...,
    "dur": round(duration_seconds, 1),
    "budget": int(duration_seconds * 7),   # 目标语言可容纳字数（中文约 7 字/秒）
} for entry in batch]
```

并在 prompt 里说明：`budget` 是这条可容纳的字数上限，明显低于上限时应优先补全信息而不是保持简短。

## P4. 8 秒合并上限废掉了流水线的核心功能 🔴

### 现象

README 把语义重组列为核心特性：

> **② 语义重组** — 先合并跨时间轴的残句，按完整语义单元翻译，避免半句独立翻译

本次运行 LLM 提出 13 个合并组，**7 组被拒，拒绝率 54%**。

### 全部拒绝都来自同一条规则

`_llm_merge_group_is_safe()` 有三条硬约束：跨度 ≤8000ms、间隔 ≤1200ms、词数 ≤60。逐组核算：

| 合并组 | 跨度 | 最大间隔 | 词数 | 拒因 |
|--------|-----:|--------:|-----:|------|
| [10,11,12,13] | 18000ms | 900ms | 57 | **跨度** |
| [14,15] | 8500ms | 0ms | 31 | **跨度**（超 500ms） |
| [21,22] | 9000ms | 300ms | 35 | **跨度** |
| [23,24] | 8800ms | 300ms | 33 | **跨度** |
| [25,26] | 9800ms | 400ms | 35 | **跨度** |
| [37,38] | 8100ms | 300ms | 22 | **跨度（只超 100ms）** |
| [43,44] | 13300ms | 600ms | 44 | **跨度** |

**没有一组是因为间隔或词数被拒**（最大间隔 900ms < 1200，最大词数 57 < 60）。7 组 100% 卡在 8 秒跨度上，其中 `[37,38]` 只超了 **0.1 秒**。

正常旁白每条 3–5 秒，**相邻两条几乎必然超过 8 秒**。这个上限等于让语义合并在真实素材上基本失效。

### 关键矛盾：这个上限并没有保护到显示质量

8 秒上限的用意应该是防止合并后字幕在屏上停留过久。但看成品：

```
成品中时长 >8s 的条目: 11/61  最长 14.9s
```

再看这 11 条从哪来：

```
转录阶段（ASR 原始输出）就已经超过 8 秒的条目: 11/67
  [(18, 9.5), (28, 9.5), (33, 11.2), (43, 9.5), (47, 10.6), (48, 12.6),
   (51, 12.7), (52, 10.0), (58, 8.3), (59, 14.9), (60, 8.3)]
ASR 最长单条: 14.9s
```

**成品里的 11 条长字幕，正好就是 ASR 原本就长的那 11 条**——合并阶段一条长字幕都没造出来，因为它被拦住了。

所以现状是：

- 对流水线**自己**的合并：8.1 秒也要硬拒
- 对**上游** ASR 输入：14.9 秒直接放行，全程不检查

同一个时长标准，一边严防死守，一边完全不设防。这个上限**没有换来任何显示质量**，只是单方面砍掉了翻译质量。

### 建议修复（两个层次）

**① 短期：让上限与下游实际容忍度对齐**

`srt_lint.LONG_DURATION_MS = 8000` 只是个**警告**阈值，14.9 秒的条目今天照样导出。合并上限却是**硬拒绝**。建议：

- 把 `MAX_LLM_MERGE_TIMESPAN_MS` 提到 12000–15000，与实际出货的字幕时长一致
- 或者改成相对判据：合并后跨度不超过"组内原有最长单条"的 N 倍，而不是绝对秒数

**② 根本解：合并只用于翻译，译文回流到原时间轴**

现在 `reflow_semantic_entries()` 把合并组的译文整体放在合并后的大跨度上：

```python
flowed = SubtitleEntry(
    index=cues[0].index,
    start_time=cues[0].start_time,
    end_time=cues[-1].end_time,       # ← 整组合成一条长字幕
    lines=[target_text, source_text],
)
```

它的 docstring 明确说明了为什么不拆：

> A translation can cover several source cues, but character length cannot
> establish which target characters belong to each cue. Do not split the
> target without **an explicit validated cue-to-target mapping**.

这个判断是对的——按字数比例硬拆译文会产生"把人名拆成两半"的灾难。**但这个映射是可以拿到的**：在翻译合并单元时，直接要求模型按 source cue id 返回已切分的译文。

```python
# 合并单元送翻译时，把组内各 cue 的 id 和原文一起给出
{"unit_id": 12, "cues": [
    {"id": 21, "src": "Go back to Newton's first law."},
    {"id": 22, "src": "An object at rest stays at rest, and an object in motion..."}
]}

# 要求返回按 cue 切分的译文，且必须覆盖每个 id
[{"unit_id": 12, "parts": [
    {"id": 21, "tgt": "回到牛顿第一定律"},
    {"id": 22, "tgt": "静止的物体保持静止，运动的物体保持匀速直线运动，除非有外力介入"}
]}]
```

这样就同时拿到两样东西：

- **翻译时**看到的是完整语义单元（合并的全部价值）
- **显示时**回到原始 cue 时间轴（不产生超长字幕）

拿到映射后，`reflow_semantic_entries` 就能安全按 id 回流；拿不到（模型没按格式返回、id 对不上、切分后拼接与整体译文不符）就退回当前的"整体放在合并跨度上"行为。这是个**可校验**的增强，退化路径已经存在。

一旦这条打通，8 秒上限就可以彻底放宽——合并不再有显示代价。

## P5. 单条中文过长 🟡

11 条超过 28 个汉字，最长 43 字：

```
[44] 43字 作为质量特性工程师，我们常被问到：飞行测试载具是否准确模拟了宇航员座位、卧铺和其他组件的位置？
[45] 34字 [47] 35字 [8] 35字 [40] 35字 ...
```

阅读速度（字/秒）没超标，因为这些条目本身时间就长。但一行 43 个汉字在屏幕上要么溢出要么折行难看。常规做法是单行 ≤20 字、最多两行。

这是 P4 的连带结果，随 P4-② 一并解决即可（回流到原 cue 后每条自然变短）。若要单独处理，可在 `srt_lint` 里加一条按标点的显示折行（只改显示，不改内容）。

## 已实施的改动与实测结果

P1、P2-① 和一处提示词改动已实施，用**同一份转录稿**重跑两次做对比（转录固定，只变翻译链路）。

### 改动内容

1. **P1** — 新增 `glossary_source_appears()`，拉丁语系要求整词命中（`(?<!\w)…(?!\w)`），
   CJK 因无词边界退回子串匹配但要求 ≥2 字符；≤3 字符的大写缩写（`R`/`HE`）额外要求原样大小写。
2. **P2-①** — `_term_rules_to_glossary_text()` 丢弃 `source == target` 的恒等映射。
3. **提示词** — `_format_glossary_prompt()` 增加「术语适用性判断」段落，明确告知术语表
   按词形匹配生成、可能包含本片中非该专业含义的词，要求逐句判断词义后再决定是否套用。

### 三轮实测

| 指标 | run1 原始 | run2 +词边界+去恒等 | run3 +词义判断 |
|------|---------:|------------------:|--------------:|
| **强制术语条数** | 26 | **15** | **14** |
| **ASR 幻觉被术语表锁定** | 3 | 2 | **0** |

### 如何解读这张表

**确定成立的（由构造保证，有测试覆盖）：**

- 强制术语 26 → 14。消失的 12 条里，8 条是纯子串误伤（`he`/`r`/`sim`/`support`/
  `balance`/`DOM`/`ratio`/`retest`），3 条是 ASR 幻觉恒等映射，都是**确定性**移除，
  不依赖模型行为。
- ASR 幻觉锁定 3 → 0。`PataBort 1` 等词在 run3 已不在术语表中，审校有权修正它们。

**不能由这三轮断定的：**

- 术语表污染 1 → 5 → 2。注意 `resistance->阻力位` 和 `structure->价格结构` 在
  **三轮的术语表里都在**（它们是真整词命中，词边界过滤按设计放行），所以 run1 的 1 处
  和 run2 的 5 处差异**纯粹是模型波动**，不是改动造成的。run3 里 `structure` 污染
  从 3 处降到 0 处、`resistance` 仍是 2 处，方向对但 n=1，**噪声量级与效应量相当，
  不足以下结论**。
- 疑似压缩/漏译 8 → 5 → 9、成品条数 61 → 60 → 58 同理，是分段阶段 LLM 在
  temperature 0.2 下的固有不确定性。

**要验证提示词改动的真实效果，需要同一素材跑 5–10 轮取均值，或换多个素材横向比。**
这里只能说：确定性缺陷已修掉，提示词改动方向合理但未经统计验证。

本次对比暴露出：**单轮运行不足以验证任何影响模型行为的改动**。术语污染在同一份
